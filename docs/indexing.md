# Verified indexer architecture (opt-in)

## Current architecture and gaps

`radar.scan` checks RPC health and samples only the first Blockscout verified-contract page. `radar.discover` scans at most 12 finalized blocks per six-hour run and only considers top-level `to=null` creation transactions. At a two-second block interval, six hours produces about 10,800 blocks, so the sample accumulates roughly 10,788 blocks of backlog per run. The existing checkpoint proves only that limited top-level sample from its bootstrap height; it explicitly records a historical gap. Its `state.json` head observation is not a coverage watermark. The existing Action writes these observations to `main` and fails if either scan stage fails. It has no contract-to-project attribution, scoring, or live alerts.

## New opt-in worker

`python -m radar.indexer --database /durable/radar.sqlite --start-block HEIGHT --max-blocks 1000 --follow` starts at an explicitly chosen finalized height and continues processing. Later runs omit `--start-block`. The worker validates chain ID 4663, uses a six-block confirmation lag, obtains every block and transaction, and requires `debug_traceBlockByNumber` with `callTracer` for every transaction. It indexes direct CREATE and nested factory CREATE/CREATE2, excluding reverted branches. Every transaction trace must agree with its receipt; direct deployments must also agree on contract address. A block is committed atomically with its deployments only after all traces and receipts pass and the block hash is rechecked. Restart rechecks the last block hash, then resumes at the next height. A changed anchor or parent hash stops the worker for manual reorg repair.

The report exposes `bootstrap_block`, `last_verified_block`, `safe_head`, `unscanned_safe_blocks`, and `historical_gap_before_bootstrap`. A nonzero backlog or historical gap is never represented as full-chain coverage. Trace API failure is fatal for that block. No fallback to receipts-only coverage exists. The SQLite database must reside on durable storage, with a single writer; a GitHub Actions runner's ephemeral disk is unsuitable. The existing scheduled Action does not run this worker.

Run `python -m radar.probe --block HEIGHT` before starting an indexer. It checks chain ID, a finalized block, and transaction-by-transaction callTracer coverage without changing a checkpoint. On 2026-11-10, the official public RPC served chain ID and block data but returned JSON-RPC `-32601` for both `debug_traceBlockByNumber` and `trace_block`. A separately configured trace-capable endpoint is required for this worker. Put its URL in `ROBINHOOD_RPC_URL` as an environment secret; do not commit it.

For sustained operation, run the worker continuously on a trace-capable node and measure blocks processed per second against chain production. Raise the configurable batch budget while lag grows, but do not trade away per-block checks. Keep the indexed blocks and candidate evidence in durable storage; for multi-worker scale, partition fixed block ranges into jobs, store range proofs, and advance the global watermark only across consecutive completed ranges. Separate backfill from tip following. Retain block hashes for reorg checks and retain deployment evidence by transaction hash plus trace path. A production database can replace SQLite when multiple writers or large-scale analytical queries become necessary.

## Candidate evidence and alerts

`radar.evidence` stores reviewer-attributed source snapshots and normalized metric reviews. A source review must include the exact contract address in its captured text. `radar.assessment` reads this separate ledger and the deployment index; candidate-submitted URLs or values have no effect on identity or score. A reviewer must independently establish that the page is first-party before recording it: the snapshot address check alone does not establish ownership. Missing reviewed metrics earn zero points. The 100-point rubric is product (20), user growth (20), on-chain activity (20), liquidity (15), revenue (15), and favorable risk (10), with a source URL, observation time, methodology, and reviewer for each metric. The current module produces only offline assessments and deduplicated *proposals*, and every indexer report sets `alert_eligible=false`. There is no delivery adapter or secret-dependent notification path.

Before live alerts, independently review first-party source ownership and metric calculations, add automated extraction from trusted sources, complete historical backfill or explicit scoped coverage rules, continuous lag SLOs, two-node trace reconciliation, reorg recovery, and an outbox delivery workflow. Keep current DeFiLlama and ChatGPT radars independent.
